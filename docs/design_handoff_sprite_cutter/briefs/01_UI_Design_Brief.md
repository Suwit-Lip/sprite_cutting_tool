# Sprite Cutter Tool — UI Design Brief

เอกสารนี้ใช้สำหรับมอบให้ Claude ออกแบบหน้าจอ (UI/UX) ของโปรเจกต์
อธิบายว่าระบบมีกี่หน้า แต่ละหน้าทำอะไร มี element อะไรบ้าง และ flow การใช้งานเป็นอย่างไร

---

## 1. ภาพรวมโปรเจกต์

**ชื่อโปรเจกต์ (ชั่วคราว):** Sprite Cutter Tool

**คืออะไร:** เครื่องมือ web application ที่รันในเครื่องตัวเอง (local) สำหรับงานทำ game asset
มีหน้าที่หลักคือ "ตัด sprite sheet" (ภาพที่รวมวัตถุหลายชิ้นบนพื้นหลังขาว/โปร่งใส)
ออกเป็นไฟล์ภาพย่อยทีละชิ้นโดยอัตโนมัติ พร้อมฟังก์ชันเสริมสำหรับสร้าง prompt
และจัดทำ tileset

**ใครใช้:** ผู้พัฒนาเกม/ศิลปิน 1 คน ใช้งานบนเครื่องตัวเอง (ไม่ใช่ระบบ multi-user
ไม่ต้อง login ไม่ต้องมีระบบสมาชิก)

**โทนของ UI ที่ต้องการ:**
- สะอาด ใช้งานง่าย เน้นการดูภาพ (image-centric)
- เหมาะกับงานสร้างสรรค์/game dev (ดู professional แต่ไม่แข็งเกินไป)
- รองรับ dark mode (ทำงานกับภาพกลางคืน/asset เกมบ่อย)
- ภาษาในระบบ: ไทย + อังกฤษผสม (technical term เป็นอังกฤษ)

**Tech stack ที่จะใช้ (เพื่อให้ออกแบบให้สอดคล้อง):**
- Frontend: Vue 3
- ไม่ระบุ component library ตายตัว — เสนอได้ (เช่น PrimeVue, Naive UI, หรือ custom)

---

## 2. โครงสร้างหน้าจอ (มีทั้งหมด 3 หน้าหลัก)

ระบบมี 3 หน้าหลัก เชื่อมกันด้วย navigation (sidebar หรือ top nav เสนอได้)

| # | หน้า | หน้าที่หลัก |
|---|------|-------------|
| 1 | **Input Gallery** | ดูภาพต้นฉบับใน input folder, เลือกภาพไปทำงาน |
| 2 | **Workspace** | พื้นที่ทำงานหลัก: ตัดภาพ, สร้าง prompt, ทำ tileset |
| 3 | **Output Gallery** | ดูผลที่ตัด/สร้างเสร็จแล้ว, ดาวน์โหลด |

> หมายเหตุ: Workspace อาจแยกเป็น sub-tab หรือ sub-mode ภายในหน้าเดียว
> (ตัด / prompt / tileset) — เสนอ layout ที่เหมาะสมได้

---

## 3. รายละเอียดแต่ละหน้า

### หน้า 1 — Input Gallery (ดูและเลือกภาพต้นฉบับ)

**จุดประสงค์:** แสดงภาพทั้งหมดที่อยู่ใน input folder ให้ผู้ใช้เลือกภาพไปทำงานต่อ

**Element ที่ต้องมี:**
- แสดงรายการภาพแบบ grid ของ thumbnail (ภาพ sprite sheet มักเป็นภาพใหญ่
  หลายร้อย px — thumbnail ควรเห็นภาพรวมได้)
- แต่ละ thumbnail แสดง: ภาพ preview, ชื่อไฟล์, ขนาด (px), ขนาดไฟล์
- คลิกที่ภาพเพื่อดูขนาดใหญ่ (modal / lightbox) หรือเพื่อเลือกไปทำงาน
- แสดง path ของ input folder ปัจจุบัน + ปุ่มเปลี่ยน folder
- ปุ่ม refresh (โหลดรายการภาพใหม่ เผื่อมีไฟล์เพิ่มจากภายนอก)
- สถานะว่าง: ถ้า folder ไม่มีภาพ ให้แสดงข้อความแนะนำ (empty state)

**Flow:** ผู้ใช้เปิดหน้านี้ → เห็นภาพทั้งหมด → คลิกเลือกภาพ → ไปหน้า Workspace
พร้อมภาพที่เลือก

---

### หน้า 2 — Workspace (พื้นที่ทำงานหลัก)

เป็นหน้าที่ทำงานจริง มี 3 โหมดการทำงาน (เสนอเป็น tab/segment ภายในหน้าได้)

#### โหมด A — ตัดภาพ (Cut Sprites) ★ ฟังก์ชันหลัก

**จุดประสงค์:** ตัด sprite sheet ที่เลือกออกเป็นชิ้นๆ อัตโนมัติ

**ปรัชญาการออกแบบที่สำคัญที่สุดของโหมดนี้:**
ผู้ใช้ **ไม่ควรต้องเดาค่าพารามิเตอร์เอง** เพราะภาพแต่ละแบบต้องใช้ค่าต่างกัน
(บางภาพวัตถุห่าง บางภาพชิดกันแน่น บางภาพขนาดวัตถุผสมกันสุดขั้ว) ระบบต้อง
ช่วยเดาค่าให้ + ให้ผู้ใช้เห็นผลสดแล้วปรับด้วยตา ไม่ใช่กรอกตัวเลขลอยๆ แล้วลุ้น
แนวคิดหลัก: **"ระบบเดาให้ → เห็นผลทันที → ปรับด้วยตา → ตัด"**

**Element ที่ต้องมี:**

1) พื้นที่ preview ภาพต้นฉบับขนาดใหญ่ (ตรงกลาง/ซ้าย)
   - แสดง **กรอบ (bounding box) ทับบนภาพ** ว่าจะตัดตรงไหนบ้าง + จำนวนชิ้นที่พบ
   - กรอบต้อง **อัปเดตแบบ realtime** ทันทีที่ผู้ใช้ลาก slider (live preview)
     ไม่ต้องกดปุ่ม preview แยก

2) แถบเดาค่าอัตโนมัติ (Auto-suggest) — แสดงเด่นด้านบน panel
   - ตอนเปิดภาพ ระบบวิเคราะห์ภาพแล้วตั้งค่าเริ่มต้นที่เหมาะให้ทันที
     ผู้ใช้เห็นกรอบที่เดาไว้แล้วตั้งแต่แรก (ไม่ได้เริ่มจากศูนย์)
   - แสดงข้อความสั้นๆ ว่าระบบมองภาพนี้เป็นแบบไหน เช่น
     "ภาพนี้วัตถุชิดกัน — ตั้งค่าระวังการรวมชิ้นให้แล้ว" หรือ
     "ภาพนี้ขนาดวัตถุผสมมาก — แนะนำใช้โหมดเลือกชิ้นเอง"
   - ปุ่ม "เดาค่าใหม่" (reset กลับไปค่าที่ระบบแนะนำ)

3) Panel ตั้งค่า (ปรับเองได้ ถ้าอยาก) — ทุกตัวมี live preview:
   - ความไวการแยกพื้นหลัง (background threshold) — slider
   - ขนาดวัตถุขั้นต่ำ (min size) — กรองเศษเล็กๆ — slider
   - ระยะเชื่อมชิ้นที่ติดกัน (group/dilation) — slider
     (มี hint: "เพิ่ม = รวมชิ้นที่แตก / ลด = แยกชิ้นที่ติดกัน")
   - padding รอบวัตถุ — number (อธิบาย: เพิ่มขอบรอบวัตถุหลังตัด ข้างละ N px)
   - toggle: เก็บเงา / ไม่เก็บเงา (ค่า default = เก็บเงา)

4) โหมดเลือกชิ้นเอง (Manual edit) — สำหรับเคสยากที่ค่าอัตโนมัติเอาไม่ลง
   - **คลิกชิ้นที่ไม่ต้องการเพื่อเขี่ยทิ้ง** (เช่น เศษ noise, หรือชิ้นที่ไม่อยากได้)
   - **เลือกหลายกรอบที่ควรเป็นชิ้นเดียวแล้วสั่งรวม** (เช่น เปลวเทียนที่แยกจากตัวเทียน)
   - (ถ้าทำได้) ลากวาดกรอบเพิ่มเองสำหรับชิ้นที่ระบบไม่เจอ
   - แนวคิด: ภาพขนาดผสมสุดขั้วบางภาพ "ไม่มีค่า minSize ที่ลงตัว" จริงๆ
     การให้คลิกเลือกเองจึงคุมได้ดีกว่า

5) Preset (ชุดค่าที่บันทึกไว้ใช้ซ้ำ)
   - บันทึกชุดค่าปัจจุบันเป็น preset ตั้งชื่อได้ (เช่น "icons แน่น", "วัตถุห่าง")
   - เลือก preset ที่เคยบันทึกมาใช้ทีเดียว เมื่อเจอภาพลักษณะคล้ายกัน

6) ปุ่ม "ตัดและบันทึก" (Cut & Save) + สถานะ loading + สรุปผลเมื่อเสร็จ
   (ตัดได้กี่ชิ้น, บันทึกไปที่ไหน) + ปุ่มไปดูที่ Output

**ข้อสำคัญด้าน UX (ย้ำ):**
- กรอบต้องเปลี่ยน **สดทันที** ตอนลาก slider — นี่คือหัวใจ ทำให้ผู้ใช้ปรับด้วยตา
  ได้โดยไม่ต้องเข้าใจว่าตัวเลขแต่ละตัวคืออะไร
- ค่าเริ่มต้นต้องมาจากการวิเคราะห์ภาพ ไม่ใช่ค่า default ตายตัวค่าเดียว
- โหมดเลือกชิ้นเองคือ safety net เมื่อ auto + slider ยังไม่พอ

#### โหมด B — สร้าง Prompt (Prompt Generator)

**จุดประสงค์:** ใช้ภาพต้นฉบับ + คำสั่งเสริม ส่งไปให้ AI ช่วยแต่ง prompt
แล้วเก็บไว้ให้ผู้ใช้เอาไป generate ภาพเองภายหลัง (ระบบไม่ generate ภาพเอง)

**Element ที่ต้องมี:**
- แสดงภาพต้นฉบับที่เลือก (thumbnail)
- ช่องกรอก "prompt เสริม" (textarea) เช่น "บ้านจอมเวทย์ theme fantasy"
- (อาจ) แสดง default prompt ที่ระบบใช้เป็นฐาน (read-only หรือแก้ได้)
- ปุ่ม "สร้าง Prompt" — ยิงไปหา AI
- พื้นที่แสดงผล prompt ที่ได้กลับมา (พร้อมปุ่ม copy)
- ปุ่ม "บันทึก" — เก็บคู่ (ภาพต้นฉบับ + prompt + เวลา) ไว้
- รายการ prompt ที่เคยสร้างและบันทึกไว้ (history) — แต่ละรายการแสดง
  thumbnail ภาพต้นฉบับ + ข้อความ prompt + ปุ่ม copy + ปุ่มลบ

**ผลลัพธ์ที่ผู้ใช้ได้:** คู่ของ "ภาพต้นฉบับ + prompt พร้อมใช้" ที่ผู้ใช้จะ copy
prompt ไปวางในเครื่องมือ generate ภาพภายนอก (เช่น ChatGPT) เอง

#### โหมด C — ทำ Tileset (Tileset Maker)

**จุดประสงค์:** เลือกภาพหลายชิ้นจาก output มาจัดเป็น tileset (ปรับขนาดเท่ากัน +
เรียงเป็น sheet) แยกโหมดพื้น (floor) และผนัง (wall)

**Element ที่ต้องมี:**
- พื้นที่เลือกภาพจาก output (multi-select grid)
- เลือกโหมด: **พื้น (floor)** หรือ **ผนัง (wall)** — layout การเรียงต่างกัน
- ตั้งค่าขนาด cell (เช่น 64×64, 128×128) — ภาพทุกชิ้นจะถูก resize ให้พอดี cell
- พื้นที่ preview ผลการเรียง tileset แบบสด
- **ต่อภาพแต่ละชิ้น:** มีเครื่องมือดัดมุมเล็กน้อย (slider สำหรับ skew/rotation/
  perspective) เผื่อภาพไหนมุม isometric เพี้ยน ให้ปรับเองทีละชิ้นได้
  - หมายเหตุสำคัญ: ระบบ **ไม่** เปลี่ยนมุมมองจากภาพหน้าตรงเป็น isometric
    อัตโนมัติ (ทำไม่ได้) — เป็นการดัดแก้มุมที่เพี้ยนเล็กน้อยเท่านั้น โดยผู้ใช้คุมเอง
- ปุ่ม "สร้าง Tileset" → บันทึกไฟล์ tileset (+ metadata) ไป output

**ข้อสำคัญด้าน UX:** เน้น preview สดและการปรับมือทีละชิ้น (human-in-the-loop)
มากกว่าการประมวลผลอัตโนมัติทั้งหมด

---

### หน้า 3 — Output Gallery (ดูผลและดาวน์โหลด)

**จุดประสงค์:** แสดงผลที่ผ่านการตัด/สร้างทั้งหมด ให้ดูและดาวน์โหลด

**Element ที่ต้องมี:**
- ผลถูกจัดกลุ่มตามภาพต้นฉบับ (เช่น folder ย่อยต่อ 1 sheet ที่ตัด)
- แสดงชิ้นย่อยทั้งหมดแบบ grid (พื้นหลังโปร่งใส — ควรมี checker pattern
  ด้านหลังเพื่อให้เห็นความโปร่งใส)
- แต่ละชิ้นแสดง: ภาพ, ชื่อไฟล์, ขนาด
- เลือกได้หลายชิ้น (multi-select) เพื่อ:
  - ดาวน์โหลดเป็น zip
  - ส่งต่อไปโหมด Tileset
- ปุ่มดาวน์โหลดทั้งชุดเป็น zip
- แสดง path ของ output folder + ปุ่มเปลี่ยน folder
- สถานะว่าง: ถ้ายังไม่มี output ให้แนะนำให้ไปตัดภาพก่อน

---

## 4. องค์ประกอบที่ใช้ร่วมทุกหน้า (Global)

- **Navigation:** สลับ 3 หน้าได้ง่าย (เสนอ sidebar หรือ top nav)
- **แสดง path ของ input/output folder ปัจจุบัน** ที่เข้าถึงได้สะดวก
- **Dark/Light mode toggle**
- **Loading / progress indicator** สำหรับงานที่ใช้เวลา (ตัดภาพ, ยิง AI)
- **Toast / notification** แจ้งผลสำเร็จ/ล้มเหลว
- **Error state** ที่อ่านเข้าใจง่าย (เช่น โฟลเดอร์ไม่มีอยู่, AI ตอบ error)

## 5. Flow การใช้งานหลัก (เพื่อให้เข้าใจการเชื่อมหน้าจอ)

```
[Input Gallery]
   อัปโหลด / เลือกภาพ sheet
        ↓
[Workspace → โหมดตัดภาพ]
   ระบบเดาค่าให้ → เห็นกรอบสด → ปรับด้วยตา (slider / คลิกเลือกชิ้น) → กดตัด
        ↓
[Output Gallery]
   ดูชิ้นที่ตัด → ดาวน์โหลด zip / ลบที่ไม่เอา
        │
        ├──→ เลือกหลายชิ้น → [Workspace → โหมด Tileset] → จัด tileset → บันทึก
        │
        └──(แยก flow)──→ [Workspace → โหมด Prompt]
                            ใส่ prompt เสริม → ยิง AI → เก็บ prompt ไว้ใช้เอง
```

## 6. สิ่งที่อยากให้ผู้ออกแบบช่วยคิด/เสนอ

- Layout ที่เหมาะกับงาน image-centric (ดูภาพเยอะ ปรับค่าเยอะ)
- **การวาง panel ตั้งค่ากับ preview ให้ปรับ slider แล้วเห็นกรอบเปลี่ยนสดทันที**
  (live preview คือหัวใจของโหมดตัด — ออกแบบให้ลื่น ไม่กระตุก)
- **วิธีนำเสนอ "ค่าที่ระบบเดาให้" (auto-suggest)** ให้ผู้ใช้เข้าใจง่ายว่าระบบ
  ตั้งค่าให้แล้ว และมองภาพนี้เป็นแบบไหน (badge/ข้อความสรุปสั้นๆ)
- **interaction ของโหมดเลือกชิ้นเอง** — คลิกเขี่ยชิ้นทิ้ง, เลือกหลายกรอบแล้วรวม,
  ให้รู้สึก direct และเห็นผลทันที (hover/selected state ของกรอบ)
- วิธีแสดง bounding box ทับภาพให้ชัดและสวย (รวมสถานะ: ปกติ / เลือกอยู่ / จะลบ)
- **UI ของ preset** — บันทึก/เลือกชุดค่า ให้เรียบง่ายไม่เกะกะ
- empty state / loading state / error state ที่ดูดี
- ระบบ component ที่นำกลับมาใช้ซ้ำได้ (thumbnail card, slider group, ฯลฯ)

---

## 7. ขอบเขตที่ "ไม่อยู่" ใน UI นี้ (กันเข้าใจผิด)

- ไม่มีระบบ login / สมาชิก / สิทธิ์ผู้ใช้
- ไม่มีฟังก์ชันตั้งชื่อไฟล์อัตโนมัติด้วย AI (ตัดออกแล้ว — ผู้ใช้จัดการเอง)
- ระบบ **ไม่ generate ภาพเอง** ในโหมด Prompt — เพียงสร้างและเก็บ prompt
- ไม่มีการแก้ไขภาพระดับ pixel (ไม่ใช่โปรแกรมวาดภาพ)
